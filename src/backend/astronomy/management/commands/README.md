# ingest_space_weather

NOAA から宇宙天気データを取得し、BigQuery に蓄積する管理コマンドです。

## 処理フロー

全体の流れは以下の 4 段階です。

### 1. 現状把握（BigQuery への問い合わせ）

BigQuery に「各メトリクス（X線、太陽風、Kp指数）はいつまでのデータを持っているか」を問い合わせます。

返り値例:

```python
{'xray_flux': '1月23日 10:00', 'solar_wind_speed': '1月23日 09:50', ...}
```

### 2. 広範囲のデータ取得（Fetch）

NOAA から直近（デフォルト 7 日間）のデータをすべて取得します。重複は気にせず、確実な範囲を取得します。

### 3. 差分フィルタリング（Deduplication）

取得したデータをメモリ上（Pandas）で加工し、**「BigQuery の最新日時より未来のデータ」** だけを抽出します。

全てのデータが既に存在する場合（＝新しいデータがない場合）、ここで処理を終了します（早期リターン）。

### 4. データの保存（Ingest）

フィルタリングで残った「真に新しいデータ」だけを BigQuery に追加（`WRITE_APPEND`）します。

---

## メリット

### ① データの重複がゼロになる（データ品質の向上）

- **以前**: 毎日実行すると過去 7 日分のデータが何度も重複して保存されていました。分析時に `DISTINCT` する必要があり非効率でした。
- **現在**: 常にユニーク（一意）な時系列データが保たれます。グラフ化や分析が非常にスムーズになります。

### ② 何度実行しても安全（冪等性・堅牢性）

- **リトライに強い**: ネットワークエラー等でジョブが失敗し再実行しても、すでに保存されたデータはスキップされるためデータが壊れません。
- **スケジュールの柔軟性**: 「1時間に1回」でも「1日1回」でも、コードを変更することなく自動的に差分だけを埋めてくれます。

### ③ 欠損（ギャップ）を防ぐ設計

取得範囲を「7日間」と広く取っているため、万が一システムが 3 日間停止しても、復旧後の最初の実行で空白期間（3 日分）を自動的に埋めることができます。

### ④ コストとパフォーマンスの最適化

- 不要なデータを Insert しないため、BigQuery のストレージ容量を節約できます。
- Insert 処理自体もデータ量が減るため、処理時間が短縮されます。

---

## 技術的なポイント

- **Pandas の活用**: 複雑な日付比較やフィルタリングを SQL ではなく Python 側（Pandas）で処理することで、柔軟かつ高速にロジックを実装しています。
- **空データ対策**: フィルタリングの結果データが 0 件になった場合に、空の DataFrame を BigQuery に投げてエラーになるのを防ぐガード処理（`if result_df.empty: return`）が入っており、安定性が向上しています。
